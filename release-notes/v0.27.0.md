## Token economy and specialist hand-back

Agents send less, the logs now record what OpenRouter actually billed, and specialists can hand a request back to JARVIS.

### Highlights

- **`edit_blog_post` edits passages, not the whole post.** It used to take the complete new file, so adding two LinkedIn drafts meant the model retyped a 24,600-character post (about 6,500 output tokens). Now it takes a list of `old_text` → `new_text` replacements. The same edit took 504 characters and 369 output tokens on Opus 5.5.
  - Text outside the replaced passages stays byte-for-byte. The full-file rewrite had silently turned no-break spaces into normal spaces, and those changes showed up as invisible "changed" lines in the approval diff.
  - Matching still works when the model retypes invisible characters or quotes, so a near-miss doesn't cost a retry turn.
- **Logged token counts and costs are what OpenRouter billed.** In streaming mode (the default), LiteLLM replaces OpenRouter's usage with its own estimate. Compared with OpenRouter's billing record, the logged cost was about 36% too low.
  - Streamed turns now keep their request ids, and the log swaps the estimate for the billing record.
  - The record appears about 10–15 s after a turn, so the CLI stats line shows the estimate marked `~`.
  - `scripts/backfill_billed_usage.py` fixes turns still estimated at exit.
  - Every logged answer says `usage_source: billed` or `estimated`.
- **Old tool calls stop riding along.** History trimming shortened old tool *results* but not the model's own tool *calls*, so a full-post edit was re-sent on every later turn (about 6,300 tokens per turn). Old tool calls are now trimmed too, keeping the JSON valid.
- **Specialists hand out-of-scope requests back to JARVIS.** An interactive specialist session can end itself with `hand_back_to_jarvis`. JARVIS then routes the user's message, with the specialist's reason, to the right agent. A request is re-routed at most once, and every hand-back is logged (ADR-038, CLI only).
- **"Apply this change?" accepts Enter again.** A terminal left in a half-raw state made Enter print `^M` and hang the confirmation. The prompt now goes through prompt_toolkit, like the `You:` prompt.
- **Token-economics docs.**
  - A fact sheet on the edit-tool savings and the usage measurement (`docs/research/token-economics-edit-tools.md`).
  - The prompt-caching plan reopened, with the March diagnosis corrected: streamed calls do cache, and the "8026 vs 8823 tokens" gap was LiteLLM's estimate.

### Tests

**2,967 collected** (2,908 in v0.26.2). New tests cover:
- passage-edit matching;
- billed-usage lookup and reconciliation;
- tool-argument trimming;
- the confirmation prompt;
- hand-back routing.

The confirmation fix was checked in a real terminal set to the broken state. Billed usage and passage edits were checked live against OpenRouter.

### Known limits

- Logs from before this release have no request ids and can't be corrected, so their costs, including the March 2026 cost report, are lower bounds.
- OpenRouter's billing record has no cache-write field, so streamed turns log `cache_write_tokens: 0`. The billed cost is exact.
- The billed-usage path in the GUI is covered by unit tests, not a live run.
- `edit_note` (vault) and the developer agent's `edit_file` still take full files.
- Specialist hand-back is CLI only.
- What left the terminal half-raw is still unknown; the confirmation prompt no longer depends on it.

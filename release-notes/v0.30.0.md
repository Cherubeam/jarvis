## Memory in the vault

JARVIS's soul and memory notes can live in the Obsidian vault, with dates and sources on every note.

### Highlights

- **Context file names, folders and the tasks path are settings.** `paths.context_files` names the six notes; subfolders and spaces are fine. `paths.tasks_file` keeps the Things-generated `tasks.md` out of the vault. With the defaults, the system prompt is byte-identical to before.
- **Frontmatter is stripped before the prompt**, so `updated`, `source`, `review-by` and the other fields cost no tokens.
- **Invalid frontmatter logs a warning naming the file.** It stays in the prompt rather than being guessed at, which used to happen silently.
- **Memory frontmatter schema** documented in `deployment.md`. Every note records when it was last true and where it came from, so later imports can tell newer facts from older ones (ADR-041).
- **The context snapshot** saved with each conversation works with a context folder outside the repo; it used to crash on such a folder.
- **Removed `paths.learned_facts`:** no code read it.

### Breaking

- A leftover `paths.learned_facts` key in `config/local.yaml` now fails validation at startup. Delete it.

### Tests

**2,854 collected** (2,822 in v0.29.0). New tests cover configured names in subfolders with spaces and en dashes, tasks read from and synced to `paths.tasks_file`, frontmatter stripping, the warning on invalid frontmatter, and a byte-for-byte check that the default prompt is unchanged.

### Known limits

- The proposal-based importer for Claude memory (HUB-03) isn't built yet; memory notes are edited by hand in Obsidian.

## JARVIS GUI Foundation — Phases 1–4

A graphical peer to the CLI. Browser-served, sharing the same agents, tools, conversation files, and approval flow.

### Get it running

```bash
uv sync --extra web
uv run jarvis-gui              # opens http://127.0.0.1:8123
uv run jarvis-gui --no-browser # serve only
```

### Highlights

- **Phase 1 — Chat shell.** FastAPI + WebSocket backend (`apps/gui/server/`), React 18 + Vite + TypeScript frontend (`apps/gui/web/`, built bundle committed). Streaming text, tool-call cards, vault-write approval diffs, command palette, light/dark + accent swap. New `apps/cli/session_factory.build_session()` shares pre-loop wiring between CLI and GUI via an injected `ConfirmationHandler`.
- **Phase 2 — Conversations browser.** Live Sidebar + two-pane History view with filterable agent / tool / date / sort facets. mtime-keyed in-memory `ConversationIndex` runs in `asyncio.to_thread`. `turn_finished` WS event invalidates the sidebar so it never goes stale.
- **Phase 3 — Dashboard / Home.** Composite `GET /api/home` (greeting + Things 3 tasks with list-key-derived priority + 7-day cost rollup + resume + recent + quick-start). Heuristic task↔conversation linking; client-side active-session exclusion.
- **Phase 4 — Sidebar Timeline mode.** Togglable `sidebarMode: 'list' | 'timeline'` tweak — 40px day-axis column with day-cost sums; cards scale 48–80px via log-bucketed token formula.

### Process

- **PR-merge policy documented:** `gh pr merge <N> --rebase --delete-branch` is the sanctioned merge command. Server-side disables `mergeCommitAllowed`.

### Tests

59 new GUI unit tests (Phase 1 + Phase 2 + Phase 3); Phase 4 was a pure frontend change. Suite goes from 1,844 → 1,935 pass.

### Compatibility

The CLI continues to work unchanged; both surfaces share the same conversation JSON, agent registry, tool groups, and config.

## Memory imports you approve

A Claude memory export no longer overwrites anything: a model proposes changes, and each one needs your yes. The conversation archive gets its own folder.

### Highlights

- **`scripts/import_claude_memory.py`** reads the 2026-09 Claude memory export. A model drafts add/update proposals per memory note and drops facts the note already covers. Code checks each proposal and marks facts older than the note as conflicts, which are shown and never applied.
- **Every change needs a yes** (`[y]es / [e]dit / [n]o / [q]uit`; edit opens the proposal for editing, and pasting works). Human oversight, EU AI Act Art. 14. Every decision is logged next to the archived export: record-keeping, Art. 12.
- **Claude projects map to vault notes by ID** (`claude-project: <uuid>` in the note's frontmatter). Project memories go through the same review and respect each note's own maintenance rules; newest-first logs get new entries at the top.
- **Raw exports are kept** in `paths.imports_dir`, without login history and account data.
- **The conversation archive has its own folder**, `03 Resources/AI Conversation Archive/`, separate from JARVIS's working data, before Cortex becomes a second reader (ADR-041 amendment).
- **Decided: one conversation index.** Cortex will hold it (HUB-02); JARVIS's own index is retired once Cortex covers its recall features.

### Removed

- `scripts/import_claude_context.py`: it overwrote the context files without comparing dates.

### Tests

**2,896 collected** (2,918 in v0.31.0; the removed importer took its 65 tests with it). A test caught that the first archive exclude pattern missed the real `light_metadata-000` folder, which would have archived account data.

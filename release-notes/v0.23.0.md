## GUI Authentication (AON-01, finding #1)

The GUI server used to accept every request and every WebSocket connection. Browsers don't enforce same-origin on WebSockets, so any page you visited could open `ws://127.0.0.1:8123/ws/chat` and drive the agent: read the vault, write notes, approve its own tool calls. This release closes that front door.

### Highlights

- **One ASGI middleware gates the whole server.** It covers every `/api/*` route, `/ws/chat` and `/docs` / `/redoc` / `/openapi.json`. Only `/`, `/auth`, `/favicon.ico` and `/assets/*` are exempt, and `/` shows a sign-in page when you aren't signed in.
- **Origin allowlist plus token, both required.** The origin check stops your own browser from being used against localhost. The token stops other machines once the server binds beyond loopback. Extra origins go in `gui.allowed_origins`.
- **Two credentials, not one.** Cookies aren't port-scoped, so the cookie carries a one-way HMAC of the token: `Authorization: Bearer` accepts only the raw token, the cookie only the derived value.
- **Two approval-hijack holes closed.** A vault-write decision with no id no longer approves whatever is pending. A decision that arrives before anything is pending no longer pre-arms an invisible, unprompted write.
- **The GUI loads `.env`.** Before, `OPENROUTER_API_KEY` in `.env` only reached the CLI.

The design is in ADR-035; how to sign in is in `docs/engineering/gui.md#authentication`. Framework hooks: OWASP Agentic Top 10 (access control), EU AI Act Art. 14 (the approval gate can no longer be bypassed; applied voluntarily).

### Tests

**2,802 collected** (from 2,581 in v0.22.0). There are new tests for the middleware over HTTP and the WebSocket handshake, and a mutation sweep of the auth code. The sweep closed the `app.py` / `state.py` / `chat_ws.py` blind spot: 115 unkilled mutants led to 84 new tests.

### Compatibility

- **The GUI now requires sign-in.** The launcher prints and opens a `Sign in:` URL; the token lives in `data/.gui_token` (or `$JARVIS_GUI_TOKEN`). Scripts must send `Authorization: Bearer <token>`.
- Binding to `0.0.0.0` requires an explicit `gui.allowed_origins` entry.
- `WebConfirmationHandler.resolve()` now requires an exact approval id and returns `False` otherwise. The shipped frontend always sends one.

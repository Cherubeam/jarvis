## Outcome tracking + prompt-include resolver

Closes the loop on advice JARVIS gives, plus the `prompt_includes` resolver lands with `.md.example` fallback.

### Highlights

- **Outcome tracking (Phase 5K)** — `track_recommendation` shared tool captures actionable recommendations as YAML-frontmatter markdown under `data/outcomes/` with `conversation_id` back-link.
- **`/outcomes` CLI command** — interactive scoring of pending outcomes past their `revisit_at` date (verdict + 1–5 quality + retro note); atomic writes; Ctrl-C safe.
- **`recall_outcomes` shared tool** — semantic search over reviewed outcomes via `OutcomeIndexer` + `OutcomeSearcher` (ChromaDB collection `outcomes`).
- **New `packages/core/frontmatter.py`** (parse / dump / `write_atomic`) and **`packages/core/date_utils.py`** (`parse_relative_date`).
- **`prompt_includes` resolver with `.md.example` fallback** — agent prompts can declare `prompt_includes:` in `meta.yaml`, with a 5-level resolution chain. Ships `voice-profile.md.example` as a starter template.
- **`outcomes:` config section** with default filesystem access rule for out-of-the-box operation.
- **CI: pytest workflow** runs on every push and pull_request — first CI workflow on the repo.

### Tests

95 new unit tests across 6 files — see [changelog.md](https://github.com/Cherubeam/jarvis/blob/main/docs/changelog.md#0160---2026-04-19) for the full breakdown.

### Compatibility

No breaking changes. Outcome tracking is opt-in via `outcomes.enabled` (defaults to `true` for new installs; existing installs need to add the section to enable).

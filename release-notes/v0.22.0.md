## [0.22.0] - 2026-09-05

The context-hub release: ADR-034 strategic positioning ("harnesses are commodities, the context is the moat"), the `HUB` initiative, `HUB-01` shipped end-to-end (Cortex as MCP server, consumed by Claude Code and JARVIS alike), plus the accumulated GUI fixes and the mutation-testing sweep from April–May.

### Changed — HUB-01 complete: Cortex consumed via MCP; bespoke HTTP path retired (2026-09-05)

- **JARVIS now reaches vault semantic search through the same `cortex-mcp` stdio server Claude Code uses** (one integration surface, per ADR-034). New generic **`shared: true` flag on `mcp.servers` entries** (`MCPServerSettings.shared`): a shared server's tools join every agent's shared toolset instead of forming an opt-in tool group — preserving the old behavior where every agent had vault search automatically. Tools arrive namespaced (`mcp_cortex__search_knowledge`, `mcp_cortex__index_status`); graceful degradation moved into the MCP server (actionable error when the Cortex service is down; agents fall back to `search_notes`). Verified live through JARVIS's own `MCPManager` against the running service.
- **Retired**: `packages/integrations/cortex/` (HTTP client), `packages/core/tools/cortex_search.py` (`search_vault_semantic`), `CortexSettings` + the `cortex:` config section in `default.yaml`, and their tests. Session factory's Cortex startup block replaced by the shared-MCP split.
- `HUB-01` marked ✅ complete in the roadmap — including the detour it earned: its first real use surfaced a Cortex retrieval-quality gap (title-blind embeddings), fixed and verified in `cherubeam/cortex` the same week (eval strict 6/6; hybrid BM25 documented there as the trigger-gated next step).

### Docs — Context-hub positioning: ADR-034, `HUB` initiative, DEV rescope (2026-08-19)

- **Adopted ADR-034 "Context Hub Positioning — Rent Coding Harnesses, Own the Context."** With coding-agent harnesses (Claude Code, Codex, OpenCode, Cowork) now commodities, JARVIS is explicitly positioned as the **personal context, memory, and workflow hub** — harnesses are rented, the context is the moat. Three concrete changes: **(1)** new initiative **`HUB`** in `roadmap.md` (HUB-01 exposes Cortex as a local MCP server per ADR-029's "MCP-ready" clause; HUB-02 adds context files + typed memory), ending copy-paste of context between JARVIS and external tools; **(2)** `developer-agent-roadmap.md` DEV-02/03 rescoped from "build our own autonomous coding harness" to "JARVIS discovers and frames work, delegates execution to Claude Code headless / Agent SDK" — AutoConfirmationHandler, planning phase, and AST-validated Python scope dropped as superseded; **(3)** `vision.md` gains an Agent Harnesses landscape section + an explicit non-goal ("not a general-purpose coding harness"), replacing the stale "not a GUI application" non-goal (the GUI shipped in `WEB`). ADR-033's crosswalk gains the `HUB` row. The 2026-07-04 deep-research dossier artifact was revised in place to match, and a standalone copy is now committed at `docs/research/jarvis-deep-research-dossier.html` (undated filename on purpose — the document carries both its prepared and revised dates). Follow-up (2026-08-20): the `HUB` section gained a **source policy — index, don't proxy**: Cortex ingests sources for cross-source semantic recall, but transactional access (Readwise actions, Miro edits) uses each source's own MCP registered directly in every client, and raw vault filesystem access remains alongside semantic search.

### Tests
- **Fixed pre-existing date-window flake in `test_detail_cost_14d_sums_only_agent_sessions`.** The fixture uses hardcoded conversation dates from 2026-04-19/20; as today drifts they exit the 14-day window in age order. The previous assertion only allowed totals of 0.0 or 0.025; after 2026-05-03 the older 0.005 fell out and the newer 0.02 still counts, yielding 0.02 — failing the test. Widened to allow {0.0, 0.02, 0.025} (the three reachable totals) and made the never-includes-researcher invariant explicit (`!= 0.01`). Was actively blocking the mutation workflow on this branch — mutmut runs `pytest -x` for baseline collection, this single failure stopped the run, every mutant came back "not checked".

### Fixed
- **JARVIS GUI — Home `ResumeCard` now resumes in-place instead of yanking to History.** Closes the inconsistency caught right after v0.21.0 shipped: the chat-sidebar and History detail-pane both fire the WS `resume` protocol, but the Home view's `Continue where you left off` card was still calling `onOpenHistory(resume.id)` and bouncing the user into a different view. `HomeView` now accepts an `onResume(fileId)` prop, wired through App.tsx to the existing `onResumeFromHistory` handler that drives the same `pendingResumeId` plumbing. Empty-state behavior (no prior session) still falls back to starting a fresh chat. Pure frontend wiring change, no backend touch, no new tests. Live-verified in browser: clicking the resume card switches to the chat view with the prior session's totals (`12 msgs · 42.127 tokens`) populated, no console errors.

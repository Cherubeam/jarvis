## Developer agent retired

JARVIS no longer has its own coding agent. Coding on JARVIS happens in Claude Code, which reads the repo's `AGENTS.md`.

### Highlights

- **`/develop` and its 16 tools are gone** ([ADR-039](https://github.com/Cherubeam/jarvis/blob/main/docs/product/decisions.md#adr-039-retire-the-developer-agent), superseding ADR-028 and amending ADR-034 §1). Removed: the developer agent and its `AutoConfirmationHandler`, the `dev_tools` group (codebase, git, project writes, pytest and mutation runners), `--auto-confirm`, the `developer` settings section in the CLI config and the GUI, and the codebase-map script. About 2,700 lines of code and tests.
- **Why:** none of its tools was called in 41 native JARVIS sessions, and no commit came from it. Yet JARVIS could delegate to it from the GUI, where untrusted vault-search text, file writes and pytest execution sat in one agent. Its write-scope check could be escaped with `..`, and `--auto-confirm` approved such writes without a human. Deleting unused write and exec permissions removes excessive agency instead of guarding it (OWASP LLM06; NIST AI RMF Manage).
- **Two roadmap items closed by deletion:** the confirmation gate on the pytest runner (AON-01), and the FilesystemGuard bypass by the developer's write tools (AON-04).
- The golden delegation case now routes a research request to `researcher`.

### Breaking

- A leftover `developer:` block in `config/local.yaml` now fails validation at startup. Delete it.

### Tests

**2,789 collected** (2,967 in v0.27.0). The six developer-tool test files (167 tests) went with the code. New tests pin that `/develop` no longer resolves and that a `developer:` settings block is rejected.

### Known limits

- The reversal trigger is recorded in ADR-039. A dispatcher to Claude Code would be rebuilt from scratch, not by restoring DEV-01; tag `v0.27.0` is the restore point.

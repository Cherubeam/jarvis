## Things via Shortcuts

JARVIS read your Things 3 tasks by opening Things' database, and macOS only allows that per app with Full Disk Access. Started from anywhere else, startup failed with `unable to open database file` and quietly cached an empty task list. This release reads Things through a Shortcut you build once, and makes failures visible.

### Highlights

- **Things through the `JARVIS Things Export` Shortcut.** JARVIS runs it with `shortcuts run` and gets your Inbox plus every scheduled task as JSON. It then splits Today (including overdue) from Upcoming, the same rule the old `things.py` library used. No Full Disk Access, no database access.
  - **Speed:** about 1 s with Things running, 1.7 s when Things has to start in the background.
  - **Setup:** build steps in `docs/engineering/deployment.md#things-3`; the decision is ADR-037.
- **Failures are visible.** A failed read names its cause (`Things tasks not refreshed: …`), caches nothing, and keeps the previous `tasks.md`. It no longer tells the model "No tasks found".
- **The GUI Home view** runs the export off the event loop, so it no longer blocks the chat.
- **The GUI bundle is committed.** The root `.gitignore` excluded `dist/`, so only `index.html` was ever tracked, pointing at a JS bundle that was never committed. Fresh clones got a GUI that couldn't load, and the frontend changes from v0.24.0 and v0.25.0 never reached the served bundle. That includes the approval-card link warnings, the agent model in the agent panel and the auto-router settings.
- **CI checks the frontend.** A new `frontend` job runs `npm ci` and `npm run build` (type-checks with `tsc -b`) and fails if the committed bundle is stale.
- **`main` is protected** by the ruleset "Protect main": PRs only, with the checks `lint`, `typecheck`, `pytest` and `frontend` required, linear history and no force-push. AGENTS.md's release steps follow suit.

### Tests

**2,870 collected** (2,894 in v0.25.0). The removed Things write-tool tests outnumber the new tests for the Shortcut runner and the mapping. The new tests mock `subprocess` and the platform, so they run on Linux CI. Locally the suite is now fully green on macOS too: the 8 tests that needed Things' database left with the write tools.

### Compatibility

- **One-time setup:** build the `JARVIS Things Export` Shortcut (steps in `deployment.md#things-3`). Until then, JARVIS starts without task context and logs why.
- **Removed:** the Things write tools (`create_task`, `complete_task`, `update_task`) and the `things-py` dependency. Read-only for now; the roadmap records how to bring writes back.
- **Grouping:** tasks in `tasks.md` are grouped by their parent (project or area) title. The Shortcuts actions don't expose areas separately.
- **Contributors** can't push to `main` directly anymore; every change needs a PR with green checks.

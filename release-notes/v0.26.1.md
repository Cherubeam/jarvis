## Fixes

Four small fixes that turned up during the September docs audit and the v0.26.0 work.

### Highlights

- **The CLI agent label shows the name again.** Rich read `[content_reviewer]` as a style tag and dropped it, so delegated agents answered under a bare `:`. The name is now escaped. The old test used "Writing", and Rich only swallows lowercase bracketed words, so it never caught this.
- **The GUI Settings editor no longer shows the retired Cortex section.** Those settings were removed when Cortex moved to MCP (HUB-01). Editing a field in that section made the save fail with a 422. The committed GUI bundle is rebuilt.
- **`meta.yaml` `temperature:` now reaches the model.** It was stored and never sent. Agents without `temperature:` still send none, so the provider's default applies, and JARVIS itself is unchanged. developer now actually runs at 0.3; strategyzer and tactics_coach send 0.7. Both GPT-6 Luna and Opus 5.5 accept the parameter (live-checked).
- **The golden harness reads its evaluation settings.**
  - `quality_threshold`, `category_thresholds` and `results_dir` come from config; `--quality-threshold` still overrides them.
  - The model under test defaults to `models.default` instead of a hard-coded Sonnet 4.5.
  - `max_cost_per_run` / `warn_cost_threshold` are removed. The harness can only estimate cost from price tables (and that estimate is $0 for the auto router), so the limits promised more than they could check.

### Tests

**2,904 collected** (2,870 in v0.26.0), with new tests for each fix.

### Compatibility

- **strategyzer and tactics_coach** now explicitly send temperature 0.7, where they used the provider's default before. Remove the line from their `meta.yaml` to go back.
- **Leftover `evaluation.max_cost_per_run` / `warn_cost_threshold` keys** in `config/local.yaml` are ignored.
- **Golden result labels:** `DEFAULT_MODEL=openrouter/x` is now labelled `x`, so both spellings group together.

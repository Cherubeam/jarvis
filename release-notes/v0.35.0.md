## Measure, then sharpen

JARVIS can now report how it is used and what it costs. The first change measured with real tool calls is in this release: tool descriptions that name where paths start.

### Highlights

- **Usage reports** in `scripts/analyze_costs.py` count native JARVIS sessions only, never imports (AON-01):
  - `--by sessions`: sessions per ISO week and front end. This is the usage measure from ADR-040.
  - `--by spend`: spend per month, split into billed, estimated and legacy turns.
  - `--by caching`: billed turns per model with their cache-read share, the baseline for prompt caching.

  How to run them is in `docs/product/metrics.md`. Run `scripts/backfill_billed_usage.py` first.
- **Each turn logs the model that answered** (`metadata.model`). Before, a pinned agent's Opus turns were recorded under the session's GPT-6 Luna (record-keeping, EU AI Act Art. 12).
- **Tool descriptions say where paths start.** The vault and blog tools name their real folders and say which tool's paths feed which; `list_blog_posts` names the blog's actual subfolders. A scratch probe sent the real tool definitions to the model and ran only the read-only tools. Given a blog-folder path, the first read failed in 5 of 5 runs before the change (GPT-6 Luna and Opus 5.5) and in 0 of 5 after. The tool schema grew 2.6%.

### Changed

- `--by source` reads `metadata.import_source`, so Claude Code imports show as `imported/claude_code` instead of `imported/other`.
- Roadmap: the OpenRouter data-policy check is deferred. It needs the owner to read the account's policies, and it blocks nothing else.

### First numbers

43 native sessions in 11 active weeks. 5 billed turns so far, all GPT-6 Luna, with 66% of their prompt tokens read from cache. There is no billed Opus turn yet, so the caching question for Opus stays open; no conclusion from 5 turns.

### Tests

**2,832 collected** (2,814 in v0.34.0).

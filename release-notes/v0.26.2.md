## `/review` and context fixes

Fixes from the first live run of the reworked `/review`, plus a smaller Things task context.

### Highlights

- **`/review` gets its evaluation back.** `evaluate_content` returned nothing on a long draft. Opus 5.5 reasons by default on OpenRouter, and its reasoning used up the skill's 4,096-token `max_tokens` before any text. The budget is now 16,000 (skill change in the spec repo); the same 3,175-word draft then got the full five-lens evaluation. An empty result now names the model's `finish_reason` instead of a bare "No evaluation generated."
- **`/review` presents the whole evaluation.** `content_reviewer` runs on `quality` (Opus 5.5), the skill's `max_tokens` and its scoring rubric reach the model, all five lenses and the rubric scores are shown, and the agent labels its own findings as its own. It no longer previews a rewrite before you ask for one.
- **Long answers print once.** Any streamed answer taller than the terminal left its top part behind when the live display stopped, so the start showed twice.
- **Smaller Things context.** Task IDs no longer go into `tasks.md`: about 20% smaller (14.7 KB → 11.7 KB for 103 tasks), sent with every request.
- **The MCP startup line counts connected servers.** A server that failed to connect is no longer counted (`from 1 of 2 servers`).

### Tests

**2,908 collected** (2,904 in v0.26.1), with new tests for each fix, including a real-terminal regression test for the double print.

### Known limits

- The evaluator fix is checked live by calling `evaluate_content` directly. A full interactive `/review` run after the fixes is still to do.
- Any skill or tool with a tight `max_tokens` on a reasoning model can fail the same way; not audited yet.

## Morning briefing

JARVIS now writes a short briefing every morning at 07:30 and shows it at the top of the GUI home screen. It's the first job that runs with nobody at the keyboard, and the first step of AON-02.

### Highlights

- **Morning briefing.** `jarvis run-job morning-briefing` gathers your Things tasks, yesterday's daily note, recommendations due for review, the career direction map and your Reader lists. One model call then writes a review of yesterday, today's priorities, open loops, career and three reading picks. With no daily note, the review is left out silently.
- **A fixed pipeline, not an agent.** Code gathers the sources and the model gets no tools, so instructions planted in an article have nothing to act on (OWASP LLM01). Source text is fenced as untrusted data, and LLM-written career themes are called hypotheses (human oversight, EU AI Act Art. 14).
- **Failure stays small.** A source that fails costs only its section. Nothing can be asked in a job, so over `budget.monthly_usd` it makes no model call. Spend lands in the ledger as `purpose: job` (record-keeping, Art. 12).
- **GUI card and settings.** The card shows when the briefing was written, its cost and any missing sources. If the job didn't run, the last briefing stays and the card says which day it's from. Settings has a new Briefing section that applies without a restart.
- **Daily schedule on macOS.** `scripts/launchd/install.sh` installs a LaunchAgent. A run missed during sleep starts on wake. It's not installed automatically: run the script once.

### Fixed

- **Model text could run code in the GUI.** The chat and briefing renderer didn't check links, so a `javascript:` URL or a quote inside a link, carried over from an untrusted source, could run in the page (OWASP LLM05). Only `http(s)` links are clickable now, quotes are escaped, and links open in a new tab.
- **Things export hang.** `shortcuts run` waited forever on an inherited open stdin, which caused timeouts at GUI start and left an old task list. Three runs that timed out at 20 s now take about 1.3 s.

### Live checks

- First run started by the clock (2026-10-31, 07:30): exit 0, no missing source, $0.0014. Runs cost $0.0014-0.0020, so about $0.05 a month.
- First run's task dates, career shares and role direction matched their sources.
- Browser: a planted briefing kept a `javascript:` link as plain text, a quote stayed inside `href` with no event handler, and nothing ran.
- Not run live: catch-up after sleep, a network that isn't up right after wake (no retry; the last briefing stays), the over-budget refusal, a source failing mid-run, and a real injection attempt. The refusal and source failure are covered by unit tests only. The renderer fix has no automated test, because the GUI has no frontend test runner.

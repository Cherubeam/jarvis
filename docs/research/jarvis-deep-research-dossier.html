01

Summary

Six weeks after the August revision, the most urgent finding is closed: the GUI now has authentication and an origin check. Most of the rest of the August audit still stands, and two new problems came to light, one in the developer agent and one in GUI approvals.

Since 19 August, 77 commits and nine tags (v0.22.0 to v0.27.0) shipped GUI authentication, vault-write oversight, billed-usage accounting, per-agent models, the OpenRouter Auto Router, Things 3 through a read-only Shortcut, and specialist hand-back. Of the 41 recommendations and findings in the August dossier, 3 are done, 5 are partly done and 30 are still open. The August roadmap assumed a steady build pace. The repo shows short bursts instead: the 77 commits fall on 12 days, 19 of them on 28 September.

The developer agent (/develop) is the largest remaining attack surface. It also had no recorded use: none of its 16 tools was called in 41 native JARVIS sessions. Its write-scope check could be escaped with .., it was enabled by default, and JARVIS could delegate to it from the GUI without anyone typing /develop. Decided and done the same day: switched off (PR #79), then removed with ADR-039 (PR #80). A dispatcher to Claude Code gets built only if a named trigger fires (§04).

Jev (TypeSafe AI, 15 September 2026) is a new kind of model. It returns typed decisions with confidence scores, not text. It suits a few runtime decisions in JARVIS, such as picking a model tier or pre-routing to a specialist. It is not a tool for planning a roadmap, and at today's usage volume nothing in JARVIS needs it yet. It is worth a one-hour smoke test with firm exit criteria. Adopting it would need an ADR that amends the provider-independence decision (§05).

The finding that reframes the roadmap JARVIS use dropped. There were 15 native sessions in February 2026, 20 in March, 2 in April, none from May to August and 4 in September, all on one day. (A first version of this revision counted imported ChatGPT and Claude conversations as use and overstated the numbers; this is the corrected count.) The question this raised, what JARVIS is still for, is now answered in ADR-040: an owned daily assistant and a place to learn and show your work. So low use steers the roadmap toward what brings you back to JARVIS, starting with the conversation archive, instead of toward shrinking it (§08).

Already there: the conversation archive

JARVIS already imports conversations. scripts/import_chatgpt.py and scripts/import_claude.py convert exports into JARVIS's own schema in data/conversations/YYYY/, with date filters, dry runs, duplicate detection and incremental Claude sync. scripts/import_claude_context.py turns Claude memories and projects into context files. The local search index (packages/core/rag/indexer.py) picks the imports up. The archive holds 162 imported conversations (67 from ChatGPT, 95 from Claude).

What is missing: the newest imported conversation is from April 2026, because every import needs a manual export and a script run. Only ChatGPT and Claude chat are covered, not Claude Code, Codex or Gemini. And the archive is reachable only from JARVIS's own index, because Cortex, which Claude Code queries, indexes the vault alone. Whether the GUI history lists imported conversations is not verified.

Shipped work the August dossier did not anticipate

  • Vault-write oversight (v0.24.0): the approval card shows the real diff and path, link changes are flagged, and a write is refused when the note changed since the agent read it. This is human oversight under EU AI Act Art. 14.
  • Cost accuracy: billed usage from OpenRouter replaces streamed estimates (PR #73), and routed turns are priced at the routed model's rate. This invalidated earlier token numbers and led to the caching re-diagnosis.
  • Model control: 2026-09 model refresh (default GPT-6 Luna, quality Opus 5.5), per-agent models in meta.yaml, and the Auto Router as an opt-in session model (ADR-036).
  • Specialist hand-back (ADR-038): specialists return out-of-scope requests to JARVIS instead of improvising.
  • Voice-profile hygiene and P7: the profile is untracked, and notes the writer drafts are tagged assist: prose.
  • Process: main is ruleset-protected, CI builds the GUI bundle, and the docs were restructured to one home per topic.

The developer agent

ADR-034 (19 August) already decided that JARVIS does not build its own coding harness. /develop was to become a thin dispatcher to Claude Code, keeping the DEV-01 tools only for tiny edits to meta.yaml and prompts. The docs were rescoped, but the code was not touched. The question now is which of three paths to take.

OptionWhat it takesSurface afterwardsFor / against
A · Thin dispatcherPrompt composer + claude -p or Agent SDK call, ~150–300 LOC (estimate)~1,550 LOC · ~190 testsCoding work could start from JARVIS front ends. Duplicates Claude Code's remote, cloud and scheduled sessions. No input source until DEV-03 exists.

Evidence of use: none. No call to any of the 16 dev tools appears in the 41 native JARVIS sessions (the other 162 files in data/conversations/ are imports, which can't contain them), no user message starts with /develop, and no commit was made by the agent. The last functional change was on 3 April. Four problems built up while it sat frozen: the roadmap's tool and test counts are wrong, AutoConfirmationHandler is documented as dropped but still ships, the prompt forbids data/context/ while the config allows it, and run_mutation_tests rewrites pyproject.toml outside the scope guard (and mutmut does not run on macOS anyway).

The “other skill repo”: you meant agent-capability-specifications. It contains no developer or coding agent: 22 skill decks, templates, scripts and practices/engineering-practices.md, which every coding harness reads and which stays. The only developer agent was the in-repo /develop.

Decision · done 2026-09-30

Retired (option C), in two steps. PR #79 set developer.enabled: false. PR #80 deleted the agent, its five tool modules, --auto-confirm and the settings (about 2,780 lines), with ADR-039 superseding ADR-028 and reversing ADR-034 §1’s “tiny-edit fast path”. The golden delegation case now routes to researcher. Tag v0.27.0 is the restore point.

Reversal trigger: build option A from scratch if you try at least 3 times in a month to start a coding task from a JARVIS-only front end that Claude Code's own remote, cloud or scheduled sessions can't serve, or if a JARVIS discovery job produces at least 5 actionable fixes a month. Until then, put the freed effort into the context export (HUB), which no harness provides.

Framing for the changelog and write-up: removing unused write and exec permissions is a direct control against OWASP LLM06 Excessive Agency and reduces attack surface under NIST AI RMF Manage. The ADR-028 write-up and tag v0.27.0 keep the git-sandbox design as portfolio evidence, so that evidence does not depend on the code staying live.

05

Jev and decision models

What Jev is. TypeSafe AI calls it a “System One” model2. You send some state and a set of typed questions. It answers each one in parallel with a typed value and a probability distribution, and it never writes prose. There are three question types3: noul (a probability that something is true), choice (up to 255 options) and score (2–10 ordered levels). Choice and score answers carry a confidence value derived from how concentrated the distribution is. The docs suggest acting automatically above 0.9 and sending anything under 0.5 to a human4.

ClaimVendorIndependent
Latency70–500 ms; “193× faster”Median 458–563 ms wall clock, ~200 ms of it network7
Price$0.042 per million input tokens, output free~$0.00002 per decision measured7
Accuracy“Never hallucinates”27/27 on a small ticket set, tied with Mistral Small (n=27, weak)
Calibration“Calibrated” (RLCD training)No published calibration metrics; none found
Usage in the wild—2,170 GitHub projects; mostly attribute judgment and scoring6

Known failure modes, as listed by the vendor5: literal reading that misses implied intent, weak counting and dates, trouble with double negatives and multi-hop reasoning, lower accuracy when the state holds irrelevant material, and answers that shift under injected instructions. German is “supported but less accurate”, which matters for a partly German vault. Unverified The research agents disagreed on the context limit (64k vs 32k), the OpenRouter endpoint (/v1/systemone vs /api/alpha/decisions) and whether access is still waitlisted or self-serve8. Retention terms and EU data location sit in a DPA nobody read.

Verdict

Use Jev for runtime classification, not for planning. Deciding a roadmap is multi-hop trade-off reasoning, which is the vendor's own weak spot. At a handful of sessions a month, no routing decision in JARVIS costs enough to optimise yet. Jev also needs its own call path, outside LiteLLM, so each call site would be Jev-specific code. Adopting it would need an ADR amending ADR-001/003 on provider independence.

Other decision techniques

  • OpenAI Decisions API (DevDay, 29 September, limited preview): the same idea on GPT-6 Luna, which is already JARVIS's default family. Unverified
  • Anthropic advisor tool20: a cheap executor escalates hard steps to Opus within one call. It fits the default/quality split, and LiteLLM supports it. Whether it works through OpenRouter is unverified.
  • For the roadmap itself, this revision used three techniques that need no new vendor: trigger-gated scoring, an adversarial skeptic and a pre-mortem (§07). They are cheap enough to repeat at each milestone.
06

Landscape since August

ADR-034's thesis was “harnesses are commodities; the context is the moat.” Six weeks of releases strengthened it and sharpened it.

Strengthens the thesis

  • Every vendor now ships a memory silo. Claude Projects gained shared project memory (17 September)12, and Codex has a memory preview. Each one is locked to one vendor, which makes a user-owned, cross-tool context store more valuable.
  • MCP 2026-07-2816 made the core stateless and standardised authorization. A future HTTP transport for HUB-02 behind Tailscale is simpler than it was. Sampling and Roots are deprecated, so don't build on them.
  • Claude Code keeps getting better at the loop14: it neutralises markup injected into MEMORY.md and caps MCP descriptions at 2,048 characters. HUB tool descriptions must fit that cap.

Weakens JARVIS-specific plans

  • Cowork merged into Claude (16 September)13, with scheduled tasks, memory and mobile access. Proactivity is no longer something JARVIS has to build to be useful.
  • Claude Code Channels15 provide Telegram access, and Remote Control reaches a local session from the phone. The JARVIS Telegram bot is only justified for JARVIS's own workflow agents.
  • Memory servers are a commodity: mcpservers.org lists 24417. The moat is the curated content and its governance, not having an MCP server.

Caching. OpenRouter now supports a top-level cache_control that moves the breakpoint forward automatically18. That could replace step 2 of the TOK plan (hand-placed breakpoints). Its sticky-routing guide (24 September) confirms step 3: send session_id on every call, because a single unused Anthropic cache write costs more than not caching19. Whether LiteLLM passes the top-level field through is unverified.

How to read the right-hand column. Vendors shipping a feature is no longer a reason for JARVIS not to build it (ADR-040). It still matters for order: build first what only JARVIS can do for you (your archive, your vault, your tasks), and build vendor-like features when they teach something you want to learn or write about.

Hosting. The August recommendation (a headless Mac as a LaunchAgent behind Tailscale) still stands, because no vendor feature reaches Things or the local vault. It is now gated on a job that actually needs it.

How this roadmap was decided

Every candidate item went through three passes, each run by a separate agent that did not see the others' reasoning until its turn.

  • Trigger-gated scoring (practice P1). Each of 38 items got value, cost and risk-reduction scores, the trigger that would justify it, whether that trigger has fired (with evidence), a verdict (now, next, gated or drop) and a confidence.
  • Adversarial skeptic. A second agent tried to refute every “now” and argue for every “drop”, checking the repo itself before ruling.
  • Pre-mortem. A third agent assumed the roadmap had failed by 31 March 2027 and wrote the failure stories, each with an early-warning signal visible today.

One weakness this method exposed: most metric-based triggers (“3 misroutes a month”) can never fire at today's handful of sessions a month. A second weakness surfaced afterwards: none of the three agents noticed that the conversation folder mixes imports with native sessions, so the first usage figures were too high. Evidence counts need a check against the data's own metadata. Every gated item below therefore names the log or script that would show its trigger firing. Items without one get deleted at the next quarterly review.

# Daily Note Entry Generation

OUTPUT ONLY the bullet-point summary. Do not include anything else.

## Rules

- DO NOT add headings, titles, or section labels
- DO NOT ask questions or request clarification
- DO NOT add explanations, commentary, or meta-text about what you generated
- DO NOT wrap the output in code blocks or callout syntax
- DO NOT include the callout header or ">" prefixes
- DO NOT repeat or rephrase any existing JARVIS callout entries — only generate new, additive content

## Format

- 3-8 bullet points in plain markdown
- Each bullet starts with `- `
- Write in first person from the user's perspective (e.g., "Explored X", "Decided to Y")
- Use `[[wikilinks]]` for related concepts, people, or projects where appropriate

## Content

- Summarize the day's conversation highlights — key topics, decisions, and insights
- Surface recurring themes or patterns across conversations
- Be concise — this is a quick reference, not a transcript
- If existing entries are provided, generate only NEW bullets that add information not already captured

## Example

- Explored Obsidian vault integration architecture for JARVIS
- Decided on five-module design: vault, callout, diff, writer, prompts
- Key insight: [[Confirmation Handler]] pattern enables GUI-readiness without complexity
- Connected to [[Personal AI Assistant]] roadmap phase 3
